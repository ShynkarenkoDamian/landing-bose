# Pixel comparison report

## Метод

`npm run build` збирає сторінку, `npm run preview` віддає production-збірку за адресою `/landing-bose/`, а `npm run pixel:check` (`scripts/pixel-check.mjs`) відкриває її в Microsoft Edge (Playwright, DPR 1, `reducedMotion: reduce`). Скрипт знімає повні сторінки на 320, 744 і 1260 px, вимірює кожен контрольований блок через `getBoundingClientRect()` і записує всі числа в [`overlays/pixel-measurements.json`](overlays/pixel-measurements.json). Очікувані значення взяті з [`spec.md`](spec.md). Допуск — 5 px; Δ — найбільша абсолютна різниця між `x`, `y`, `width` і `height`.

## Було → стало

Стан «було» виміряно окремо на коміті `99eebe2` (останній коміт перед серією pixel-фіксів), «стало» — на поточному HEAD після `f9b11ab`. Обидва виміри зроблені тим самим способом на тих самих ширинах.

## Перевірка на регресії

Перед комітами pixel-правок знято baseline поточного стану (скриншоти, виміри й diff) і після прибирання дублювань у стилях виміри повторено. Порівняння всіх числових полів на 320 / 744 / 1260 і 360 / 414 / 600 / 900 / 1024 / 1440 / 1920 / 2560 дало 0 розбіжностей, більших за 0.011 px. Отже, прибирання не змінило геометрію, а правки категорій, банера й контактів не погіршили жодної ширини, що вже збігалася.

## Залишкові відхилення та межі порівняння

- Мобільні секції після Recommended накопичують до +3.98 px через дробові line-height у підписах і текстах; це в межах допуску.
- 744 px: spec для Why buy direct дає `x: 73`, ширину 287 px; сітка дає `x: 72` і 288 px. Розбіжність 1 px зберігає прив’язку до колонок.
- 1260 px: spec для Contact us дає 326 px, чотири колонки сітки — 324 px. Різниця 2 px.
- Мобільний Figma-банер має власну ширину 322 px з позицією −1 px і обрізається фреймом до 320 px. У браузері видимий блок — 320 px; вертикальна позиція кадру збігається з tolerance.
- Джерело банера в проєкті — `banner-bottom.jpg` 1260 × 456 px (у spec згаданий спільний JPEG 1920 × 1080 px). Сюжет і кадрування звірені з наданими mobile/tablet crop references, але деталізація JPEG/AVIF відрізняється від Figma.
- `object-position` для фото галереї та банера порахований з матриць Image logic; це не вимірювана геометрія. Точність кадрування треба підтвердити візуально в PerfectPixel — це позначено в `docs/checklist-audit.md` як «ПОТРЕБУЄ МОЄЇ ПЕРЕВІРКИ».
- Figma-кадри містять курсор над Send; за spec `Cursor / Mouse` не є елементом сторінки, тому в браузерний знімок він не доданий.
